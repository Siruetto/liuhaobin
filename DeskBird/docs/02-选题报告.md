# 选题报告：报时鸟（DeskBird）

## 一、选题背景：一次真实的调研

选题不是拍脑袋。做上一版"办公小助手"时，我们反复遇到同一类问题：工具再多、回答再好，
用户真正要的是"别忘了"和"别打断我"。

为了确认这不是我们自己的错觉，我们做了一件事：用问卷调研身边仍在学习的朋友，
回收 46 份有效问卷。

调研结论（摘要，原始数据存档在问卷后台）：

| 现象 | 比例 |
| --- | --- |
| 有过"忘记作业截止 / 会议 / 报名"的经历 | 92% |
| 觉得手机闹钟、待办"到点容易被刷走 / 忽略" | 79% |
| 学习时不想掏手机，希望"说一句就记下来" | 65% |
| 觉得纯文字提醒太安静，希望"主动开口 / 有声音" | 58% |

最常见的三类"该记没记"：作业截止（82%）、临时待办（67%）、会议活动（54%）。

一句话说明调研结论：大家不缺工具，缺的是"到点会自己开口"的提醒。

## 二、要解决的问题

把"要记住的事情"从人脑和手机上，转移到一件桌面常驻、会开口提醒的东西上。

- 记：免提语音，说一句就记，不打断学习；
- 提醒：到点主动播报 + 桌面气泡，不是沉默的弹窗；
- 做：查课表、算数、记笔记、看时间这些小事，直接替你完成。

## 三、为什么值得做（价值与情怀）

大学生的时间被切得很碎：课表、作业、社团、报名，全靠自己记，忘一次就麻烦。
一个"主动开口"的助手，本质上是把"记性"外包出去，让人能专注当下。
对赶 DDL 的人来说，被温柔地提醒，比被错过更有温度。

## 四、竞品分析

| 产品 | 能做什么 | 缺什么 |
| --- | --- | --- |
| 手机闹钟 / 待办 | 到点响 | 被动、容易被刷走、和课表不打通 |
| Siri / 小爱等通用助手 | 泛对话 | 没有课程场景，没有"到点主动播报"，数据在厂商端 |
| 滴答清单 / 番茄钟 | 清单很强 | 记事情仍要手动打字，没有免提语音，没有实体音箱 |

我们的差异：垂直校园场景 + 主动语音播报 + 桌面常驻 + 可接实体音箱。

## 五、创新点

1. 从"问答"到"主动服务"：不是等你来问，而是到点自己开口；
2. 桌面常驻 + 免提语音：学习时不打断心流，比手机 App 更有存在感；
3. 可接硬件（ESP32 音箱）：让提醒"有实体"，亮灯 + 播报；
4. 复用上一版智能体架构：把"能说会做"和"提醒调度"接在一起，不是从零开始。

## 六、核心功能（杀手级功能）

这是整个选题最亮眼的地方，也就是评分里常说的"杀手级功能"。
到点主动开口提醒，而且链路是闭环的：

> "提醒我周五 22:00 交软工作业" → 解析出时间 + 内容 → 存进日程 → 到点桌面弹窗 + 语音播报
> "周五 22:00 了，该交软工作业啦" → 支持"再提醒我一次 / 已完成"。

它让产品从"工具"变成"搭子"：不是被你问，而是主动惦记你。

## 七、可行性

### 技术可行性

- 上一版"办公小助手"已经跑通：双规划器（大模型 function calling + 离线规则）、9 个工具、
  MCP、网页界面、51 个测试，全部只用 Python 标准库；
- 这次新增的三块都有现成方案：提醒调度（定时器 + SQLite）、语音（云端 ASR/TTS，
  无网时本地兜底）、硬件（ESP32 + 音箱模块）；
- 团队分工明确，上一版的架构可以直接复用。

### 时间可行性

从需求确认到第一版可演示，按三阶段推进（见团队展示），每阶段都有可验收的交付物。

### 风险与对策

| 风险 | 对策 |
| --- | --- |
| 语音识别不准 | 先做"文字优先、语音兜底"，识别失败时转文字输入 |
| 到点播报依赖电脑开机 | 桌面端常驻 + 硬件端独立运行，二选一都有提醒 |
| 大模型接口费用 / 无网 | 离线规则模式兜底，核心提醒不依赖大模型 |
| 硬件调试耗时 | 硬件是加分项，先保证桌面端完整，再扩展 |

## 八、一句话总结

上一版解决了"会做"，这一版要解决"会惦记你"。
