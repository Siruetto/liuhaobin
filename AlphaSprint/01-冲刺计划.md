## 一、此前工作的总结与思考

前两次团队作业已经完成需求、原型、UML、数据库设计和 100 份问卷调研，但主要成果仍是设计与原型。站在 Alpha 冲刺起点，我们确认了三个问题：

1. 静态原型不能证明工具真的执行、提醒真的触发，必须把主要链路接到真实后端。
2. 上一版办公小助手已有 `Agent / Planner / ToolBox / Memory` 和 9 个工具，适合复用，但缺少提醒、语音和硬件能力。
3. 页面看起来完整，不等于用户能用。提醒时必须看得见、听得见，失败时也必须能继续使用文字。

这次冲刺的改进方向是“先完成核心闭环，再补加分项”：

- 把文字对话、工具调用、提醒入库和到点通知接到同一个运行版本。
- 保持原有 9 个工具，并增加课表查询，共 10 个；提醒作为核心服务，不额外膨胀工具数量。
- 先完成浏览器语音降级，再评估 ESP32 硬件联动。
- 每个验收项必须对应自动化测试或手工复现步骤。

## 二、冲刺目标

| 目标 | 完成标准 |

| 可演示 | 7 分钟答辩演示和 3 分钟 Vlog 可离线执行 |
| 发布 | 仓库记录语义化版本 `v0.1.0-alpha.1` 和发布说明 |

## 三、改进方案

### 1. 架构改进

- 继续复用 `Agent / Planner / ToolBox / Memory`。
- 新增 `Scheduler`，负责 SQLite 持久化、到期扫描和周期重排。
- 新增 `Voice` 能力，浏览器使用 Web Speech API，失败后降级为文字。
- `Device` 先保留接口设计与模拟状态，硬件实机作为加分项，不阻塞桌面端。

### 2. 交互改进

- 首页同时展示聊天、今日提醒、下一次提醒和语音入口。
- 到期提醒使用置顶气泡，提供“已完成”和“10 分钟后再提醒”。
- 工具调用在回复下方展示真实执行结果，避免“看起来会做”。
- 增加日程、工具、记忆三个独立视图，便于答辩演示。

### 3. 质量改进

- 调度时间显式注入，测试不依赖真实等待。
- API 使用标准库 `ThreadingHTTPServer`，没有第三方运行依赖。
- 使用一键验收脚本同时跑测试、启动服务并检查公开 API。
- 每个版本只发布能演示、能回归的增量。

## 七、冲刺完成定义

只有同时满足以下条件，才把对应任务标记为完成：

1. 代码已提交，提交信息说明改变和验证方式。
2. 自动化测试或手工验收有记录。
3. 主分支可启动，演示不依赖开发人员私有机密。
4. 新增功能与 A1-A10、TC-01-TC-14 至少一项有映射。
5. 大进展打一个语义化版本 Tag，并更新发布说明。
